# Value vor Feature

Die wichtigste Regel. Wichtiger als Hook-Formeln, wichtiger als Struktur.

**Nicht erklären, WAS etwas macht. Erklären, WAS DER ZUSCHAUER DAVON HAT.**

---

## Der Unterschied

| Mechanik (zu technisch) | Value (so gehört es ins Skript) |
|---|---|
| "Es scannt deinen Code gegen 100 Sicherheitsregeln" | "Du musst niemanden mehr fragen, ob dein Code sicher ist" |
| "Hängt sich in jede Session ein und übergibt die Daten an einen Agenten" | "Es vergisst nie wieder etwas über deine Projekte, du musst nichts doppelt erklären" |
| "Funktioniert über eine Schnittstelle mit 25-facher Effizienz" | "Du sparst dir Stunden Arbeit und langfristig hunderte Euro" |
| "246 Bausteine, 61 Agenten, 76 Befehle" | "246 Bausteine, die du sofort für deine eigenen Projekte nutzen kannst" |

Die rechte Spalte ist nicht ungenauer. Sie ist übersetzt.

---

## Die Value-Formel

Bei jedem Punkt, der ins Skript kommt, vier Fragen:

1. **Was kann es?** → das ist die Mechanik
2. **Was habe ich konkret davon?** → das Ergebnis
3. **Was spare oder vermeide ich dadurch?** → der Schmerz, der wegfällt
4. **Was ist das Krasseste daran?** → der Wow-Moment

**Antworten 2 bis 4 kommen ins Skript. Antwort 1 höchstens als Brücke, in einem Halbsatz.**

---

## Der Value-Schwanz

Selbst eine nackte Zahl bekommt einen Nutzen angehängt:

- ❌ "Über 8.000 Sterne auf GitHub."
- ✅ "Über 8.000 Sterne auf GitHub, und du kannst es sofort kostenlos benutzen."

Die Zahl allein ist kalt. Mit Nutzen dahinter wird sie zum Argument.

---

## Wo der Value sitzen muss

**Früh.** Nicht erst am Ende. Wer den Nutzen bis Sekunde 40 aufspart, verliert die Leute bei Sekunde 15.

Grobe Verteilung:
- Hook: das **Versprechen** auf Value
- Re-Hook: die **Bestätigung**, dass es sich lohnt (Zahl, zweites Versprechen)
- Body: der **eigentliche** Value
- Verstärker: der **größte** Value, bewusst aufgehoben

---

## Eine Sache tief schlägt fünf flach

Bei einem Tool, einem Trick, einer Sache: **ein bis zwei Punkte tief erklären**, mit konkreten Beispielen. Nicht fünf Punkte oberflächlich abhaken.

Muster, das trägt:
> "Funktioniert ziemlich simpel. Erst gibst du [Input]. Das kann zum Beispiel [A], [B] oder [C] sein. Dann passiert [Y]. Und was es wirklich stark macht, ist [größter Value]."

Die Beispiele sind der Punkt. "Das kann zum Beispiel A, B oder C sein" macht abstrakt greifbar.

Bei echten Aufzählungen (5 Tools, 3 Fehler) ist Durchnummerieren richtig. Dann aber pro Punkt eine Aussage **und** eine Wirkung, nicht nur den Namen.

---

## Ehrlichkeit ist Teil des Value

Ein Nutzen, den es nicht gibt, fällt auf dich zurück. Vor jedem Versprechen:

- Geht das heute wirklich, oder ist es angekündigt?
- Geht das in seinem Land, mit seinem Plan, ohne Warteliste?
- Ist es kostenlos, oder nur die Testversion?

Im Zweifel nachschauen statt annehmen. Und wenn eine Einschränkung existiert, gehört sie ins Skript. Ein ehrlicher Vorbehalt kostet drei Sekunden und rettet die Glaubwürdigkeit.

---

## Was Value zerstört

- **Mechanik im Hook.** Der häufigste Fehler.
- **Feature-Listen ohne Wirkung.** "Es kann A, B und C" ohne "damit kannst du".
- **Erfundene Beispiele.** Ein ausgedachter Kunde, ein ausgedachtes Ergebnis. Fällt auf und ist nicht reparierbar.
- **Hype statt Nutzen.** "Revolutionär" ist kein Value, sondern die Abwesenheit von Value.
- **Geld-Versprechen.** "Verdien X Euro damit" ist selten belegbar. Zeit ist der ehrlichere Rahmen: gesparte Stunden kann man nachrechnen.
